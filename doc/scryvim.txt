1. INTRODUCTION                                                *scryvim-intro*

scryvim helps you build decks in plain-text decklists:

- card name completion (any LSP completion engine),
- a results popup for a Scryfall query that inserts the chosen cards,
- mana costs as inlay hints and full card text on hover,
- sorting cards by mana value,
- counting the cards that match a Scryfall query, and mana symbols by color.

Lookups use a local copy of Scryfall's Oracle Cards bulk data, so typing
never hits the network; only search and count query Scryfall. scryvim is not
produced by or endorsed by Scryfall.

==============================================================================
2. REQUIREMENTS                                         *scryvim-requirements*

- Neovim 0.11 or newer.
- `curl` and `gzip` on $PATH.
- Optional fuzzy pickers for search results: snacks.nvim, telescope.nvim,
  fzf-lua (see |scryvim-results|).

Run |:checkhealth| scryvim to verify.

==============================================================================
3. DECKLIST FORMAT                                            *scryvim-format*

Files ending in `.dec` or `.deck` get the `deck` filetype. Any buffer can opt
in with `:set filetype=deck`.

Lines are one of:

  card     `4 Lightning Bolt`, `4x Lightning Bolt`, `Lightning Bolt`,
           `4 Lightning Bolt (M10) 146`, `4 Lightning Bolt [M10]`,
           `SB: 2 Duress`
  section  `Deck`, `Sideboard`, `Commander`, `Companion`, `Maybeboard`
           (case-insensitive, optional trailing `:`)
  comment  `// ...` or `# ...`
  blank    empty or whitespace only

Set codes and collector numbers are preserved but ignored for lookups.

4. COMMANDS AND MAPPINGS                                    *scryvim-commands*

                                                                    *:Scryvim*
:Scryvim search [query]                                  *:Scryvim-search*
    Search Scryfall (full Scryfall syntax) and show the results in a popup
    (|scryvim-results|). Prompts for a query when none is given; the prompt
    starts with your last search this session so you can tweak it (<C-u>
    clears it, see `search.prefill`). Chosen cards increment an existing line's count, or are inserted as
    `1 <name>` below the cursor.

                                                            *scryvim-results*
    The results popup is an ordinary normal-mode buffer, one card per line,
    with the card under the cursor previewed beside it. Move with `j`, `k`,
    `gg`, `G`, `<C-d>` or any other motion, and search with `/`, `?`, `n`
    and `N`. In the popup:

      <Tab>       mark or unmark the card and move down
      <S-Tab>     mark or unmark the card and move up
      {Visual}<Tab>
                  mark or unmark the selected cards
      <CR>        add the marked cards, or the card under the cursor when
                  none are marked
      {Visual}<CR>
                  add the selected cards
      q  <Esc>    close without adding

    Marks show in the sign column as `ScryvimPickMark` (linked to
    |hl-Special|). Cards already in the deck start with how many copies
    it lists (`4x`), counting every section and either name of a
    multi-face card, highlighted as `ScryvimInDeck` (linked to
    |hl-DiagnosticOk|). Fuzzy pickers show the same count. Leaving the popup closes it. Set `picker` (see
    |scryvim-config|) to use a fuzzy picker instead.

:[range]Scryvim sort                                       *:Scryvim-sort*
    Sort by mana value. Without a range, sorts the block under the cursor.
    Sections, comments and blank lines divide blocks; each block is sorted
    on its own: spells by mana value then name, then lands by name, then
    unknown cards in their original order.

    On a count line such as `// Removal ({query})` (see
    |scryvim-count-lines|), gathers the cards below it that match {query}
    into a block directly under it, sorted the same way. Cards above the
    line stay put, so a stack of count lines can peel the deck into
    groups, top to bottom. A blank line separates the
    block from cards that were already under the line. A count line in the
    main deck takes main-deck cards only; one inside a Sideboard or
    Maybeboard section takes cards from that section.

:[range]Scryvim count {query}                             *:Scryvim-count*
    Count the cards that match {query} (full Scryfall syntax), by quantity:
    20 Mountains and 5 other red sources make 25 for `produces:r`. Without a
    range, counts the whole buffer except Sideboard and Maybeboard sections
    and `SB:` lines; with a range, counts every card line in it.

    The query runs on Scryfall, limited to the deck's card names, in
    batches of about 45 names. Results are kept for the session, so
    counting again after an edit only asks about new cards. Needs network
    access.

                                                        *scryvim-count-lines*
To keep counts in the deck, add comment lines of the form
`// <label> (<query>)` (or `# <label> (<query>)`), which read like section
headers. Each line shows its total at the end, named by the label
(`40 Red sources`), or `40 cards` without one. Totals are counted like
|:Scryvim-count| without a range, and update a second after you stop
typing. Query errors show on their line, including
terms Scryfall doesn't understand, such as a misspelled keyword, rather
than counting as if the term weren't there. Example: >
    // Removal (otag:removal)            12 Removal
    // Red sources (produces:r)          40 Red sources
    // (t:creature)                      18 cards
<
The query is the parenthesized group that ends the line, so it can hold
parentheses of its own: >
    // Cheap spells ((t:instant or t:sorcery) mv<=2)
<
It needs at least one Scryfall keyword or operator (`:`, `=`, `<`, `>` or
`!`), so a comment like `// cut these (too slow)` stays a plain comment.
The older `// count <label>: <query>` form still works.

Turn this off with `counts = false`.

:[range]Scryvim mana                                       *:Scryvim-mana*
    Count the mana symbols in the cards' mana costs by type, by quantity,
    to help work out how many sources each color needs. Covers the same
    lines as |:Scryvim-count|. Counted locally; no network access.

    Each symbol counts once for its type: white, blue, black, red, green,
    colorless `{C}` and snow `{S}`. Generic mana (`{2}`, `{X}`) doesn't
    count. Hybrid symbols split between their halves: `{R/G}` is 0.5 R and
    0.5 G, and `{2/R}` is 0.5 R, since the generic half doesn't count.
    Phyrexian symbols count half: `{R/P}` is 0.5 R, and `{G/W/P}` is 0.25 G
    and 0.25 W. Cards with more than one mana cost (adventures, split and
    modal double-faced cards) count each.

                                                         *scryvim-mana-lines*
A `// count mana symbols` (or `# count mana symbols`) line shows the same
totals at its end, updated with the deck: >
    // count mana symbols                {W} 12  {R} 23.5  {C} 2
<
They also turn off with `counts = false`.

                                                        *scryvim-card-lines*
A `// count cards` (or `# count cards`) line shows the number of cards in
the deck, by quantity, split into lands and nonlands. It covers the same
lines as |:Scryvim-count| without a range, so the sideboard and
maybeboard are left out. The split shows once card data is loaded: >
    // count cards                       60 cards  24 lands  36 nonlands
<
They also turn off with `counts = false`.

:Scryvim pane                                              *:Scryvim-pane*
    Toggle the preview pane, a split on the right of the tab that follows
    the cursor in deck windows:

    - on a card line, the card, as |vim.lsp.buf.hover()| shows it but
      with more room: a rule under the type line and a blank line
      between abilities, below a nonland card its odds of being cast
      on curve (|scryvim-on-curve|), and with `pane.tags` on, the card's
      Scryfall oracle tags, the names `otag:` takes (|scryvim-tags|),
    - on a count line (|scryvim-count-lines|), the total and the cards it
      counts, most copies first,
    - on a `// count mana symbols` line, the totals and each type's share
      of all the symbols, as a percentage and a bar,
    - on a `// count cards` line, the deck size and every card in the
      deck.

    Other lines leave the pane as it is. After an edit the pane waits a
    second, like count lines. `:q` in the last other window closes the
    pane too. Set its width with `pane.width`.

    With `pane.auto_open`, on by default, the pane opens with every deck
    when the editor is at least `pane.min_columns` wide (|'columns'|, 100
    by default). When the editor narrows past that the pane closes, and
    when it widens again the pane comes back, or opens beside a deck,
    unless it was closed by hand. `:Scryvim pane` works at any width.

                                                        *scryvim-on-curve*
    On curve odds follow Frank Karsten's hypergeometric model: the chance
    of casting the card on the turn equal to its mana value, seeing 7
    cards plus one a turn after the first on the play, one more on the
    draw, with no mulligans. Casting needs as many mana sources as the
    mana value, with a different source for each colored symbol: a dual
    land pays either color, but only one symbol. Hybrid symbols take
    either color; Phyrexian and `{2/X}` symbols need no colored source.
    Below the odds, on the play, the two halves: the chance of drawing
    enough sources, and the chance of having the colors once you have
    enough sources, which is the figure Karsten's tables aim at 90% for.
    Last, the sources of each color.

    Sources are the main deck's lands, by the mana they produce, plus
    mana creatures and rocks with a lower mana value than the card. Lands
    that search for lands, such as fetch lands, count as every color.

:Scryvim update                                          *:Scryvim-update*
    Download and rebuild the card data now, and the oracle tags
    (|scryvim-tags|) unless `pane.tags` is off.

:Scryvim info                                              *:Scryvim-info*
    Show card count, Scryfall data timestamp and cache age.

scryvim defines no default keymaps. These are provided:

    <Plug>(scryvim-search)    normal mode               *<Plug>(scryvim-search)*
    <Plug>(scryvim-sort)      normal and visual mode    *<Plug>(scryvim-sort)*
    <Plug>(scryvim-pane)      normal mode               *<Plug>(scryvim-pane)*

Example: >lua
    vim.keymap.set('n', '<leader>ms', '<Plug>(scryvim-search)')
    vim.keymap.set({ 'n', 'x' }, '<leader>mo', '<Plug>(scryvim-sort)')
    vim.keymap.set('n', '<leader>mp', '<Plug>(scryvim-pane)')
<
==============================================================================
5. LSP FEATURES                                                  *scryvim-lsp*

scryvim runs an in-process language server named `scryvim`, enabled for the
`deck` filetype through |vim.lsp.enable()|. It provides:

- completion of card names,
- hover with the card's Oracle text, the formats it is banned or
  restricted in, and whether it is a Commander Game Changer
  (|vim.lsp.buf.hover()|),
- mana costs as inlay hints (|lsp-inlay_hint|),
- a "Sort by mana value" code action (|vim.lsp.buf.code_action()|),
- warnings for unknown card names (|vim.diagnostic|),
- with `type_colors` on, card names colored by card type
  (|lsp-semantic_tokens|, see |scryvim-type-colors|).

6. CONFIGURATION                                              *scryvim-config*

Configure with `vim.g.scryvim` or `require('scryvim').setup()`; the latter
wins. `setup()` is optional. Defaults: >lua
    {
      extensions    = { 'dec', 'deck' },
      auto_download = true,     -- fetch card data on first use
      max_age_days  = 7,        -- refresh in the background after this
      inlay_hints   = true,
      colors        = true,     -- see |scryvim-colors|
      type_colors   = false,    -- see |scryvim-type-colors|
      icons         = false,    -- see |scryvim-icons|
      diagnostics   = true,
      counts        = true,     -- see |scryvim-count-lines|
      picker        = 'buffer', -- see below
      search        = { max_pages = 3,     -- 175 cards per page
                        prefill = true },  -- prompt starts with last search
      hover         = { max_width = 60 },  -- columns; 0 for no limit
      pane          = { width = 50, auto_open = true, min_columns = 100,
                        tags = false }, -- see |scryvim-tags|
      cache_dir     = vim.fn.stdpath('cache') .. '/scryvim',
    }
<
`picker` decides how search results are shown:

    'buffer'      the built-in results popup, |scryvim-results|
    'auto'        the first installed of snacks.nvim, telescope.nvim and
                  fzf-lua, else |vim.ui.select()|
    'snacks', 'telescope', 'fzf_lua'
                  that fuzzy picker; <Tab> marks, <CR> adds
    'select'      |vim.ui.select()|, one card at a time

`picker` may also be a table with a `pick(items, opts)` function, where opts
has `prompt`, `format_item(card)`, `preview(card)` (markdown) and
`on_choose(cards)`.

7. CARD DATA                                                    *scryvim-data*

On the first `deck` buffer, scryvim loads `cards.json` from `cache_dir`. If it
is missing and `auto_download` is set, it downloads Scryfall's Oracle Cards
bulk file and builds a stripped copy in a child Neovim process. Language
features return nothing until the data is ready, then refresh.

While data is being checked, downloaded, built or loaded, the `scryvim`
language server reports LSP progress, which shows in |vim.lsp.status()| and
in progress UIs such as fidget.nvim. Hovering a card meanwhile says which
step is running. Loading happens in small slices, so the editor stays
responsive.

Caches built by older scryvim versions are used as they are and rebuilt in
the background, since they lack fields newer features need.

When the cache is older than `max_age_days`, it is used immediately and
refreshed in the background. A failed update leaves the existing cache in
place; the error is shown in |:checkhealth|.

                                                            *scryvim-tags*
Oracle tags in |:Scryvim-pane| are off by default; set `pane.tags = true`
to show them. Card objects carry no tags, and the tag list comes from an
endpoint Scryfall doesn't document as a public API. With tags on, the
first card the pane shows downloads Scryfall's oracle tag list (about
23 MB) and builds `tags.txt` in `cache_dir`, in a child Neovim process. The
pane says the tags are loading meanwhile and fills them in when they are
ready. Like the card data, the list is refreshed in the background after
`max_age_days`, and |:Scryvim-update| refreshes it too. Without
`auto_download` it is only fetched by |:Scryvim-update|. A failed download
is not retried until then; the pane and |:checkhealth| show the error. With
`pane.tags` off (the default) the list is never downloaded.

9. COLORS                                                    *scryvim-colors*

With `colors` on, mana symbols are colored by their color wherever scryvim
shows them: the mana cost after each card line, the hover window, and the
search results list and preview (the built-in popup, snacks.nvim,
telescope.nvim, fzf-lua).
Card names, counts and set codes keep the normal text color.

Hybrid symbols are split at the `/` and each half takes its own color:
`{U/B}` shows `{U/` blue and `B}` black, and `{2/R}` shows `{2/` colorless
and `R}` red. Phyrexian symbols take their color (`{G/P}` is green). Generic,
`{X}`, `{C}` and `{T}` symbols are colorless. Each color has a highlight
group:

    ScryvimManaWhite        ScryvimManaGreen
    ScryvimManaBlue         ScryvimManaMulticolor
    ScryvimManaBlack        ScryvimManaColorless
    ScryvimManaRed

The mana costs after card lines replace the inlay hints, since inlay hints
are drawn in a single color; each symbol uses `LspInlayHint` with the color
group on top. Set `inlay_hints = false` to hide them entirely. The fzf-lua
picker runs in a terminal, so it uses the groups' foreground colors.

The default colors come from your colorscheme, so they follow it when you
switch. Each color is taken from the first of these the colorscheme sets,
falling back to a built-in palette for 'background':

    White         `g:terminal_color_11` (bright yellow), then
                  `g:terminal_color_3` (yellow), then DiagnosticWarn
    Blue          `g:terminal_color_4`, then DiagnosticInfo
    Black         `g:terminal_color_5` (magenta)
    Red           `g:terminal_color_1`, then DiagnosticError
    Green         `g:terminal_color_2`, then DiagnosticOk
    Multicolor    `g:terminal_color_3` (yellow), then DiagnosticWarn
    Colorless     |hl-Normal| foreground

White mana is yellow and colorless mana (generic, `{C}`, `{T}`) is the text
color, since a pale white and a dim gray are hard to read, above all as
|scryvim-icons|.

The terminal colors (|terminal-config|) are the colorscheme's own red,
green, blue and so on, which is why they come first. Override any group in
your config or colorscheme, for example: >lua
    vim.api.nvim_set_hl(0, 'ScryvimManaBlack', { fg = '#9a7fc0' })
<
With `colors = false`, mana costs are plain inlay hints and nothing else is
colored.

                                                              *scryvim-icons*
With `icons = true`, mana symbols show as Nerd Font icons
(https://www.nerdfonts.com, version 3.2 or later) wherever scryvim shows them:
mana costs after card lines, hover, the pane, count lines and search
results. They are mostly Material Design icons:

    {W}  sun 󰖙          {C}  rhombus 󰜌
    {U}  water drop 󰖌   {S}  snowflake 󰜗
    {B}  skull         {P}  Φ
    {R}  fire 󰈸
    {G}  tree 󰔱        {T}  tap 󱞬, {Q} untap 󱞨
                        {E}  energy 󱐋

Generic mana and `{X}` show as plain text without their braces: `{2}{R}` is
2 󰈸. Nerd Font's circled numbers are drawn too small to read next to
the other icons; to use them anyway, override them (see below).

Each part of a hybrid or Phyrexian symbol gets its icon, keeping the slash:
`{W/U}` is 󰖙/󰖌 and `{R/P}` is 󰈸/Φ. Symbols with a part that has no icon,
such as `{HR}` or `{Y}`, stay as text. Colors apply to the icons as
they do to the text.

Nerd Font icons draw wider than the one cell Neovim gives them, so a symbol
followed by other text gets a space after it: `{R}{R}` is 󰈸 󰈸, not 󰈸󰈸.

`icons` may be a table of overrides, keyed by symbol part. `true` shows the
part as plain text and `false` keeps it as `{…}` text. Otherwise use a single
character, since buffers conceal the `{R}` text with it: >lua
    icons = { R = '', P = false }  -- nf-fa-fire
    icons = { ['1'] = '󰲠', ['2'] = '󰲢' }  -- nf-md-numeric_N_circle
<
In buffers the `{R}` text stays and is concealed (|conceal|), so it shows
where 'conceallevel' is 0, and on the cursor line where 'concealcursor'
doesn't conceal it.

                                                        *scryvim-type-colors*
With `type_colors = true`, the language server marks each card name with its
card type as a semantic token (|lsp-semantic_tokens|), and Neovim colors the
name with that type's highlight group. A card with several types uses the
first that applies, in this order:

    land, creature, artifact, enchantment, planeswalker, battle, instant,
    sorcery

so Dryad Arbor is a land and an Artifact Creature is a creature. Multi-face
cards use their front face. Cards with none of these types (tokens, emblems)
and unknown cards are not colored.

Each type's group links by default to a group your colorscheme already
styles:

    @lsp.type.land.deck           String
    @lsp.type.creature.deck       Type
    @lsp.type.artifact.deck       Constant
    @lsp.type.enchantment.deck    Function
    @lsp.type.planeswalker.deck   Statement
    @lsp.type.battle.deck         Special
    @lsp.type.instant.deck        Identifier
    @lsp.type.sorcery.deck        PreProc

Relink or recolor any of them: >lua
    vim.api.nvim_set_hl(0, '@lsp.type.land.deck', { link = 'Comment' })
<
Changing `type_colors` takes effect after restarting Neovim.

10. STATUSLINE                                           *scryvim-statusline*

The deck's size and mana symbols can show in the statusline or winbar of
deck windows, with no count line in the deck: >
    60 cards  {W} 12  {R} 23.5
<
Like |scryvim-card-lines| and |scryvim-mana-lines|, they leave out the
sideboard and maybeboard. Mana symbols show once card data is loaded, in
their colors with `colors` on (|scryvim-colors|), and as icons with `icons`
on. Outside deck buffers, and for decks with no cards, the text is empty.

In 'statusline' or 'winbar', as a `%{% %}` item: >lua
    vim.o.statusline = "%f %m%=%{%v:lua.require'scryvim'.statusline()%} %l:%c"
<
Or only in deck windows, from `after/ftplugin/deck.lua`: >lua
    vim.wo.winbar = "%{%v:lua.require'scryvim'.statusline()%}"
<
With lualine.nvim, use the `scryvim` component: >lua
    require('lualine').setup({
      sections = { lualine_x = { 'scryvim', 'filetype' } },
    })
<
Options, passed as `statusline({opts})` or as lualine component options
(`{ 'scryvim', lands = true }`):

    cards    `60 cards`, default true
    lands    `24 lands`, default false
    mana     mana symbols by type, default true

The lualine component also takes `colored = false` for plain mana symbols.

`require('scryvim.statusline').text({buf}, {opts})` gives the same text
without highlights, for other statusline plugins.
